---
title: Updating upstream icons
description: Move a collection to a new upstream version and review what changed.
---

Upstream versions are pinned, and the package's build generates the icons
from them. Only the package's `exports` are committed.

## npm collections

Lucide, Tabler, Phosphor and Heroicons are updated by Dependabot, in one pull
request. The "Icons changeset" workflow generates the icons at the base and
at the pull request, and commits the changeset: a major bump when icons are
removed or renamed, a minor one when icons are added, a patch otherwise,
with the icons listed. Read the list, then merge.

To update by hand, change the exact version in `pnpm-workspace.yaml`'s
catalog, run `pnpm install`, then `pnpm build`. The build lists the icons
added and the icons removed or renamed against your previous build. Add a
changeset (`pnpm changeset`) with the bump to match. The workspace waits two
days before installing a new release (`minimumReleaseAge`).

If the update adds or removes a style, the build changes the `exports` of
`packages/icons/package.json`: commit them. CI fails otherwise.

## Material Symbols

Dependabot can't update it. Change `MATERIAL_COMMIT` in
`packages/icons/scripts/sources/material.ts` to a commit of
google/material-design-icons, build, and add a changeset as above. The first
build after a change fetches the commit's tree and the needed files into
`packages/icons/.cache/`, about 20 seconds; later builds reuse them.

## Checks

The build fails on any icon it can't convert. CI also fails when the build
changes the committed `exports`. If generation fails on an icon, see
[Adding a collection](/docs/guides/adding-a-collection) for what to do instead
of skipping it.
